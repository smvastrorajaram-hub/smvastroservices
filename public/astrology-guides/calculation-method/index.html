How SMV ASTRO Calculates Charts, Nakshatra, Dasha and Panchangam

1. Start with complete birth inputs

A chart calculation starts with the recorded local birth date and clock time, together with the birthplace's latitude, longitude and time-zone treatment. A town name alone is not the astronomical input: the engine needs coordinates. The historical civil-time offset matters because local clock rules have changed in some places and years.

SMV's calculation flow validates the date, time and coordinate ranges, resolves the local-time offset supplied for the selected place, converts the local clock reading to UTC, and then obtains Julian Day values for the astronomical calculation. Readers comparing two reports should keep the original local date, local time, coordinates and time-zone offset together.

The IANA Time Zone Database explains why historical local-time rules should be resolved by location and date rather than assuming that a present-day UTC offset applied in every year. IANA Time Zone Database.

2. Calculate sidereal planetary positions

The SMV calculation source sets the sidereal mode to Lahiri before calculating planetary longitudes. The main engine uses Swiss Ephemeris data when the required files are available and has a Moshier fallback path when they are not. The browser-offline calculation package uses a local WebAssembly provider configured for Lahiri sidereal calculations. The engine reports its calculation mode; the exact numerical result can depend on the available ephemeris data and the submitted inputs.

Lahiri is an ayanamsa choice: it defines the reference offset used to express longitudes in the sidereal zodiac. It is not the same thing as the house system, a language setting, or an interpretation rule. The term “Thirukanitham” is used in contemporary Tamil astrology discussions for computed approaches, but that label alone does not identify every software implementation detail. This page documents the SMV implementation rather than claiming that every historical school uses identical procedures.

For technical reference, see the Swiss Ephemeris programmer documentation and the published SMV ASTRO source repository.

3. Convert a sidereal longitude into Rasi, Nakshatra and Pada

After a sidereal longitude is calculated, SMV normalises it to the 0°–360° zodiac circle. Each of the twelve Rasis spans 30°. The 27 Nakshatras divide the same circle into equal spans of 13°20′ (360° ÷ 27), and each Nakshatra has four padas of 3°20′ (360° ÷ 108). The Moon's sidereal longitude is used to identify the birth Nakshatra and pada.

Worked example — Moon at 45°30′ sidereal longitude
Rohini begins at 40°00′ and ends at 53°20′. The Moon is therefore 5°30′ inside Rohini. Pada 1 spans 40°00′–43°20′ and Pada 2 spans 43°20′–46°40′. A longitude of 45°30′ falls in Rohini, Pada 2. This is a mathematical illustration using the engine's equal-division rule, not a real person's birth chart.

When a longitude lies close to a Nakshatra or pada boundary, small changes in birth time, time-zone handling, coordinates or ayanamsa can move the result into the adjacent division. A useful report should let a reader check the submitted inputs and the calculation convention.

4. How the Vimshottari Dasha balance is derived

The SMV Dasha calculation identifies the Moon's Nakshatra lord, measures how far the Moon has progressed through that Nakshatra, and calculates the unelapsed portion of the lord's traditional period. The Vimshottari sequence used by the engine is Ketu 7, Venus 20, Sun 6, Moon 10, Mars 7, Rahu 18, Jupiter 16, Saturn 19 and Mercury 17 years, totalling 120 years.

The current SMV date calculation uses a 360-day Savana year for Dasha date arithmetic. This convention is important when comparing start and end dates with a calculator that uses a different year-length convention.

Worked example — same illustrative Moon longitude, 45°30′
The Moon is 5.5° into Rohini, whose lord is the Moon. Rohini spans 13°20′ (13⅓°). Progress through the Nakshatra = 5.5 ÷ 13⅓ = 0.4125. The remaining fraction = 1 − 0.4125 = 0.5875. The Moon's Vimshottari period is 10 years, so the remaining balance is 10 × 0.5875 = 5.875 Savana years, or 5.875 × 360 = 2,115 Savana days under this implementation's date convention. This demonstrates the arithmetic only; it does not predict an event or describe an actual person's chart.

Bhukti (Antardasha) periods are subdivisions within the major Dasha. The period lord must be interpreted with its sign, house ownership, placement, strength and the rest of the chart; a single Dasha label is not a complete prediction.

5. Panchangam formulas used by the calculation

The calculation uses the Sun's and Moon's sidereal longitudes. Let S be the Sun's longitude and M the Moon's longitude, with angular values normalised to 0°–360°:

  • Tithi segment: floor(((M − S) mod 360°) ÷ 12°) + 1. Each tithi occupies 12° of Sun–Moon elongation.
  • Karana segment index: floor(((M − S) mod 360°) ÷ 6°). Each karana occupies half a tithi, or 6°; its traditional name depends on the repeating karana sequence.
  • Yoga segment: floor(((M + S) mod 360°) ÷ (360° ÷ 27)) + 1. Each yoga occupies 13°20′ of the combined longitude.
  • Nakshatra and Pada: the Moon's sidereal longitude is divided into 27 equal Nakshatra spans and four equal padas per span.
Worked example — Sun at 10°, Moon at 43°
Elongation = 43° − 10° = 33°. The Tithi segment is floor(33 ÷ 12) + 1 = 3. The Karana segment index is floor(33 ÷ 6) = 5, which is the 30°–36° interval. The combined longitude is 53°; the Yoga segment is floor(53 ÷ 13⅓) + 1 = 4. These are formula demonstrations, not an almanac entry for a specific date and place.

Vara implementation note: the current SMV Panchang calculation assigns the weekday from the selected civil calendar date. Some traditional Panchangam conventions assign the day using sunrise. Do not assume that every festival-specific sunrise or observance rule is applied by the weekday label alone. Sunrise and local day-part information are calculated separately using the selected location.

6. How to compare two reports fairly

  1. Use the same birth date and the most reliable recorded local time.
  2. Use the same birthplace coordinates and the correct historical time-zone offset.
  3. Compare the ayanamsa and whether each engine used Swiss Ephemeris or its stated fallback.
  4. Compare the raw sidereal longitudes before comparing Rasi, Nakshatra, Pada or Dasha labels.
  5. Compare the house system separately; a planetary longitude and a bhava framework are different calculation layers.
  6. For Panchangam, compare the date, location, Sun/Moon longitudes and whether a source shows the running element or the value at a prescribed time.

If a result differs, identify which input or convention differs before deciding that a calculator is wrong. Avoid changing several settings at once.
